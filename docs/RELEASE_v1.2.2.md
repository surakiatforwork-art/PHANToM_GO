# PHANToM GO v1.2.2

วันที่: 2026-06-30 • Stable • versionCode 29

## สรุป
เพิ่มความเสถียรของการส่งเส้นทาง (Google Maps/ตำแหน่ง) จากเครื่องหลักไปยังเครื่องจอ ให้แน่ใจว่าจอได้รับและเปิดจริง ไม่ใช่แค่เขียนคำสั่งขึ้นคลาวด์สำเร็จ

## มีอะไรใหม่
- **ส่งเส้นทางแบบมีการยืนยัน (ack) + ลองใหม่อัตโนมัติ**: เครื่องหลักจะรอให้เครื่องจอยืนยันว่าได้รับ/เปิดแล้ว ถ้าไม่ตอบในเวลาสั้น ๆ จะส่งซ้ำ (รวม 3 ครั้ง: ทันที, ~1.5 วินาที, ~4 วินาที) คำว่า "ส่งแล้ว" จึงหมายถึงจอรับจริง
- **กันเปิดซ้ำ**: การส่งซ้ำของการแชร์เดียวกันใช้รหัสคำขอเดียวกัน (clientRequestId) เครื่องจอจะเปิด Google Maps แค่ครั้งเดียวต่อการแชร์ แม้ได้รับคำสั่งซ้ำ
- **แชร์หลายเส้นทางติดกันได้**: การแชร์คนละครั้งใช้รหัสคนละตัว จึงไม่ถูกยุบรวมกัน

## ทดสอบที่รันจริง (2 เครื่อง)
- แชร์ปกติ → จอเปิด Maps ครั้งเดียว, เครื่องหลักขึ้นสำเร็จเมื่อจอยืนยัน
- กรณีตอบช้าจน "ส่งซ้ำ" จริง → จอยังเปิดครั้งเดียว (log: รับคำสั่งซ้ำแต่ข้ามการเปิด)
- แชร์ 2 เส้นทางติดกัน → ส่งถึงทั้งคู่ ไม่ยุบรวม
- `assembleDebug assembleRelease lintDebug testDebugUnitTest` ผ่านทุกโมดูล; ติดตั้งบนเครื่องจริง 2 เครื่อง (Main/Display)

## ข้อจำกัดที่ทราบ
- ถ้าเครื่องจอออฟไลน์นานเกิน ~7 วินาที เครื่องหลักจะรายงานล้มเหลว (ไปเส้นทางสำรอง Wi‑Fi/คิวเดิม) แม้ภายหลังจออาจเปิดคำสั่งที่ค้างได้เมื่อกลับมาออนไลน์
- การกันเปิดซ้ำใช้หน้าต่างเวลาประมาณ 3 นาทีต่อรหัสคำขอ

## Firebase
**ไม่ต้องแก้ rules** — โครงสร้างกฎปัจจุบันรองรับฟิลด์เพิ่ม (clientRequestId/attempt) และการยืนยันของเครื่องจออยู่แล้ว (ยืนยันด้วยการทดสอบจริง)
